# Контактна форма Фундації · пакет для refinement

## 1. Короткий опис

Щоб надіслати звернення зі сторінки «Контакти», відвідувачу потрібно вказати номер телефону, а резюме чи портфоліо можна додати за бажанням. Працівник Фундації має отримати сповіщення з новими даними й мати змогу відкрити документ, якщо відвідувач його додав.

## 2. Зачеплені області

| Область | Що розглядаємо |
| --- | --- |
| Сторінка «Контакти» | Обов’язковий телефон (IN-01, RULE-04) і можливість надіслати звернення з документом або без нього (IN-02, RULE-10). Один PDF — умова вправи. |
| Перевірка звернення | Узгодити результати форми й сервера для телефону та вкладення. Згода зараз перевіряється у формі. Обсяг обробки CV та перевірку згоди на сервері уточнює Q-07. |
| Сповіщення працівнику | IN-03, RULE-11 охоплюють нові дані в листі. Потрібні окремі перевірки вмісту листа, його отримання й доступу до доданого документа. |
| Спільна форма | Партнерські звернення й отримання нот використовують той самий компонент. Межі зміни визначають OUT-01 і Q-09. |
| Мова й доступність | UK та EN охоплюють підписи, підказки й помилки (NFR-06). Для NFR-05 запропоновано перевірити клавіатуру, фокус, контраст та озвучування результатів. |

[Межі й потік у специфікації](spec-contact-form.md#2-межі)

## 3. Залежності

| Підстава | Що потрібно для рішення або перевірки |
| --- | --- |
| CON-01, CON-02 | Визначити межу PDF у байтах (Q-01). Для міжнародного телефону макет допускає 7–15 цифр після плюса, сервер — 10–15. Рішення щодо розбіжності потрібне за Q-22. |
| DEP-01, DEP-02 | Узгодити одержувачів і спосіб передавання PDF, обсяг згоди, строк і початок зберігання, перелік копій (NFR-01, NFR-02). Погодити дії зі шкідливим або неперевіреним PDF (NFR-04, Q-23). |
| DEP-03 | Навчальний обробник повертає відповідь без доставки листа. Для AC-28 потрібне спостереження в тестовій скриньці, для AC-10 і AC-25 — відмова надсилання та перевірка того, що бачить відвідувач. |
| DEP-04 | Погодити формулювання UK/EN для AC-11. Окремо визначити мову сповіщення працівнику та мову відповіді відвідувачеві (Q-02, Q-15). |
| DEP-P-01 | Для вузького PoC запропоновано підтвердити доступність локальної форми, тимчасової конфігурації й прямого запиту. |

**Припущення на погодження.** ASM-02 пропонує 5 МБ, ASM-03 — обмежений доступ і приватне посилання, ASM-04 — видалення через 90 днів після закриття. ASM-05 стосується збереження введених даних і PDF після збою. Навчальна бізнес-метрика ASM-01 також очікує погодження. [Реєстр припущень](spec-contact-form.md#6-припущення)

## 7. Критерії приймання

Це заплановані перевірки. Передумови, точні значення та прив’язки до RULE наведено в [сценаріях специфікації](spec-contact-form.md#8-сигнали-приймання).

| Критерії | Спостережуваний результат і статус |
| --- | --- |
| AC-01, AC-02, AC-03 | Для порожнього телефону форма показує помилку, сервер відхиляє відсутній, порожній або пробільний номер. Для неповного номера форма пояснює помилку формату. |
| AC-04, AC-17, AC-18 | Склад листа й видимість нормалізованого телефону в AC-04 залежать від Q-05. Без PDF лист не пропонує завантаження. За наявності PDF отриманий файл має побайтово збігтися з надісланим. |
| AC-05, AC-06, AC-07, AC-19, AC-20, AC-21 | Справжній PDF розміром L−1 або L байтів приймається. При L+1 або PNG форма показує помилку, прямий запит відхиляється. Сервер також відхиляє текстовий файл із назвою та заявленим типом PDF. L очікує Q-01. |
| AC-08, AC-11, AC-27 | Знята згода дає помилку біля прапорця. При порожньому телефоні, завеликому PDF, PNG або відсутній згоді браузер не надсилає запиту. Тексти перевіряють у UK та EN після погодження за Q-02. |
| AC-09, AC-22, AC-16 | Поки триває запит, кнопка заблокована й повторне натискання не збільшує кількість запитів. Коректне звернення без файлу отримує підтвердження. |
| AC-10, AC-25, AC-26, AC-28 | При відмові пошти видно помилку мовою форми, а успіх приховано. У тестовій скриньці очікується нуль листів за відхиленим через телефон або вкладення запитом і рівно один за успішним. |
| AC-23, AC-24 | Після збою запропоновано знову дозволити надсилання та зберегти введені ім’я, email, телефон і повідомлення. Потрібне рішення за Q-04. Збереження PDF перевіряється окремо. |
| AC-13, AC-14, AC-29, AC-30, AC-33 | Умовний варіант із приватним посиланням: лист відображає наявність вкладення, телефон і PDF доступні відповідно до ролі, а звернення без PDF не пропонує файл. Залежить від Q-03 і Q-05. |
| AC-15, AC-31, AC-32 | Умовний строк ASM-04: після його спливу телефон і PDF видалено з погоджених місць, а старе посилання не відкриває PDF. Для приймання потрібні рішення за Q-06 і Q-25. |
| AC-34, AC-35, AC-36, AC-37, AC-38 | Регресія поточної поведінки: межі імені 2–50 та повідомлення 10–1000, розбіжність для email з плюсом, повернення додаткового текстового поля й заголовок «New Contact Form Submission» за відсутності типу форми. |
| AC-12 | Архівний номер. Два історичні приклади стосуються партнерського звернення без телефону й PDF та отримання нот без контактного запиту. Межа зміни відкрита за OUT-01, Q-09. |

## Definition of Ready для refinement

**Пакет готовий до refinement.** Перевірено 26.11.2026 у робочій копії гілки `day-4`. Базовий коміт (`git rev-parse --short HEAD`) — `a4e605f`. На момент перевірки пакет і специфікація були локальними незакоміченими файлами.

| Опис зрозумілий без попередніх матеріалів | У розділі 1 названо сторінку, обов’язкову дію відвідувача, необов’язковий документ і результат для працівника. |
| Кожен Blocker враховано | У розділі 5 позначено один відкритий Blocker зі статичного аналізу. Для відповіді 500 перевірити обидва результати: відвідувач бачить помилку (AC-10), підтвердження успіху залишається прихованим (AC-25). Результат такого прогону ще не зафіксовано. |
| Кожен активний AC можна перевірити | Для всіх 37 AC у матриці є дія та спостережуваний результат. Для умовних сценаріїв зазначено відкрите питання. Наприклад, AC-05 перевіряє приймання на межі L, а AC-19 — відхилення на L + 1 байт. Значення L у байтах має визначити власник Q-01. |
| У матриці є зв’язки в обидва боки | Кожне з 18 RULE має джерело і принаймні один чинний AC. Кожен із 37 чинних AC має RULE. AC-12 залишився в архіві. Для NFR-04 і NFR-05 окремі критерії очікують рішень за Q-23 та Q-24. |
| Відкриті питання мають власників і дати | У розділі 4 для всіх 25 питань наведено відповідальну роль і запропоновану дату. Для Q-01 та Q-09 дати вже минули. На зустрічі потрібні рішення власника продукту або нові строки. |
| Докази мають чіткі межі | Розділ 8 фіксує зникнення підказки на п’яти символах і відповідь сервера 200 на шести. Надсилання рівно п’яти символів і отримання листа потребують окремих перевірок. |
