## Результат повторного запуску:

Повторна звірка п’яти тверджень із § 3 та § 8 підтвердила кожне як опис запланованої перевірки. Для AC-19 відкритим залишається значення L. Нижче окремо звірено числові умови попередньої відповіді.

| Число або межа | Результат звірки | Позначка |
|---|---|---|
| Один PDF; L − 1, L і L + 1 байт | В умові вправи йдеться про один PDF. Для справжнього PDF у коректному зверненні L − 1 і L допускаються. На L + 1 форма показує помилку, API відхиляє файл. Q-01 наводить 5 000 000 та 5 242 880 байтів як варіанти для уточнення. Обидва варіанти залишаються відкритими (IN-02, CON-01, AC-05, AC-06, AC-19). | Grounded |
| 7–9 цифр; мінімум 10 | CON-02 фіксує діапазони 7–15 для макета і 10–15 для сервера. Цифри рахують після плюса, включно з кодом країни. Цільове рішення для 7–9 цифр відкрите (RULE-05, Q-22). | Grounded |
| Три варіанти порожнього телефону | Відсутнє поле, порожній рядок і самі пробіли перевіряють окремо. API має повернути помилку телефону для кожного варіанта (RULE-04, RULE-16, AC-02). | Grounded |
| Чотири окремі випадки; нуль запитів | Порожній телефон, завеликий PDF, PNG і знятий прапорець згоди перевіряють окремо. Для кожної спроби очікується нуль запитів браузера (AC-27, Q-01). | Grounded |
| Один запит | Поки перший запит триває, повторне натискання залишає загальну кількість запитів рівною одному (AC-22). Після обриву зв’язку результат першої спроби уточнює Q-21. | Grounded |
| Нуль або один лист | Після відмови API через відсутній телефон чи хибне вкладення очікується нуль листів. Для кожного успішного звернення з PDF або без нього очікується рівно один лист у тестовій скриньці (AC-26, AC-28). | Grounded |
| 90 днів після закриття | Число й подію відліку взято з ASM-04. Статус у попередній відповіді вказано правильно. Погоджений строк відсутній (NFR-02, Q-06). | Invented |
| Чотири теми, 15 крайових випадків | Це кількість тем і рядків у попередній відповіді за форматом вправи. Нумерація AC, RULE, Q та інших записів слугує для посилань. | Grounded |

### Крок 4. Повторний аналіз після додавання Q-25

| Попередній результат | Результат за оновленою специфікацією | Позначка |
|---|---|---|
| Крайовий випадок 13 охоплював різні дати подання й закриття. | Тепер окремо розглядається звернення без зафіксованої дати закриття. Якщо Фундація вибере закриття як початок відліку, для такого звернення потрібна відповідь на Q-25. Підстав підставляти дату подання немає. | Grounded (Q-06, Q-25, NFR-02) |
| 90 днів після закриття — припущення ASM-04. | Припущення зберігає свій статус. Умовні AC-15, AC-31 та AC-32 описують перевірки за наявності дати закриття. | Invented для строку |

**Критерії приймання.** Решта полів коректні, згоду надано. Для перевірки розміру потрібне погоджене L у байтах.

|---|---|---|---|
| AC-02 | **Дано:** телефон відсутній, порожній або містить лише пробіли. **Коли** API отримує кожен варіант окремо, **тоді** відхиляє звернення з помилкою поля телефону. | RULE-04, RULE-16 | Grounded |
| AC-19 | **Дано:** справжній PDF має розмір L + 1 байт. **Коли** він надходить безпосередньо до API, **тоді** сервер відхиляє файл із помилкою розміру. | RULE-10, RULE-16, Q-01 | Grounded |
| AC-28 | **Дано:** відвідувач подав коректне звернення з PDF або без нього. **Коли** надсилання успішно завершилося, **тоді** в тестовій скриньці є рівно один лист для цього звернення. | RULE-10, RULE-12, RULE-14 | Grounded |
| AC-31 | **Дано:** на момент зафіксованого закриття PDF збережено. **Коли** від цієї дати минуло 90 днів, **тоді** за навчальним припущенням PDF відсутній у погоджених копіях. Погодження строку, початку відліку й переліку копій очікує відповіді на Q-06. | RULE-10, RULE-13, NFR-02, ASM-04, Q-06 | Invented |
