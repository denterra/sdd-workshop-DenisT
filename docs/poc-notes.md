# Нотатки PoC: що я побачив у запущеному застосунку

## Проба 1: обов'язковий телефон

Що змінив: для перевірки RULE-04 тимчасово змінив два файли.

- У `ContactForm.tsx` зробив `phoneNumber` обов’язковим у даних форми. Прибрав `.optional()` і дозвіл на порожній рядок. Після видалення крайніх пробілів схема вимагає непорожній номер. До підпису поля додав `*`, а для програм читання з екрана — `aria-required`.
- У `validateContactData.ts` прибрав умову `if (phoneNumber)`, яка пропускала перевірку порожнього або відсутнього номера. Тепер серверний валідатор перевіряє телефон у кожному зверненні за чинними правилами типу, формату й довжини.

Що побачив у браузері: на `/en/contacts` поле було підписане «Phone number *», а над формою була підказка «* – required fields». Заповнив ім’я, email і повідомлення, поставив позначку згоди та натиснув «Send request» із порожнім телефоном. Під полем з’явилося «This field is required», фокус перейшов на телефон. Форма залишилася відкритою з введеними даними.

Що показали тести: запустив `npx jest app/lib/utils/validateContactData.test.ts --coverage=false`. Із 14 тестів 13 пройшли. Упав лише `should return no errors for valid input`: у прикладі заповнено ім’я, email і повідомлення, а поле `phoneNumber` відсутнє. Тест очікував порожній список помилок `[]`. Після зміни RULE-04 серверний валідатор повернув `["Invalid phone number"]`, бо телефон тепер обов’язковий.

## Проба 2: мінімальна довжина повідомлення

Що змінив: Знизив мінімум повідомлення з 10 до 5 символів у схемі форми (`ContactForm.tsx`) і в серверній константі `MESSAGE_MIN_LENGTH` (`app/constants/validation.ts`). Виправив число в обох підказках `messageMinLength` (`i18n/messages/en.json` та `uk.json`). Сервер бере мінімум із тієї самої константи і для перевірки, і для тексту помилки.

Що побачив у браузері: На `/en/contacts` для `Test` (4 символи) під полем з’явилося «The comment must contain at least 5 characters». Коли дописав п’ятий символ (`Tests`), підказка зникла. З указаним телефоном і позначкою згоди натиснув «Send request» для `Tests!` (6 символів). Форма показала «Your request has been sent». У журналі локального сервера для цієї спроби зафіксовано `POST /api/collaboration 200`.

Що показали тести: Команда `npx jest app/lib/utils --coverage=false` з налаштуванням `bail: 1` виконала 8 із 31 набору: 107 тестів пройшли, 2 впали. Повторний запуск `npx jest app/lib/utils --coverage=false --bail=0 --runInBand` виконав усі 31 набір: 195 тестів пройшли, впали ті самі два у `validateContactData.test.ts`.

- **Проба 2.** `should return error if message is too short` очікує помилку довжини для `Too short` (9 символів із пробілом). За нового мінімуму повідомлення проходить перевірку довжини. У результаті була лише помилка «Invalid phone number», бо в прикладі пропущено телефон.
- **Проба 1.** `should return no errors for valid input` очікує порожній список помилок для звернення без телефону. Валідатор знову повернув «Invalid phone number».
